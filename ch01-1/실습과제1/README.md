# 실습과제

## 1. 강의노트에서 잘 몰랐던 용어에 대해 자세히 조사하시오.
**Generic Programming**   
제네릭 프로그래밍은 자료형에 국한되지 않는 알고리즘과 자료구조를 만드는 프로그래밍 방식이다.

예를 들어 정렬 알고리즘을 생각해보면 정렬되는 집합들은 항상 같은 자료형이 아니다.

어느 경우에는 int 정렬, 다른 경우에는 double, string 등 정렬 대상에 어떤 자료형이 올지는 모르는 일이다.

그래서 자료형에 상관없이 사용할 수 있는 방식이 생겼는데 그게 제네릭 프로그래밍이다.

**STL(Standard Template Library)**    
C++에서는 STL 이라는 제네릭 프로그래밍을 지원하는 라이브러리가 존재한다.

STL 라이브러리는 거의 모든 것이 template으로 작성되어 있는 것이 특징이다.

template은 컴파일 시점에서 실제 자료형에 맞는 코드를 생성해 사용할 수 있어, 제네릭 프로그래밍을 지원하기에 편리하다.

## 3. 클래스와 객체가 무엇인지 설명하시오.
**클래스**    
객체를 생성하기 위한 설계도 역할을 하는 사용자 정의 자료형이고 변수와 함수를 포함할 수 있다. 즉, 클래스는 설계도라고 표현할 수 있다.

**객체**    
클래스를 기반으로 생성된 실제 실체를 의미하고 클래스에 정의된 속성과 기능을 사용할 수 있다. 즉, 객체는 그 설계도를 바탕으로 실제로 만들어진 결과물이다.

## 4. 절차지향 프로그래밍 언어와 객체지향 프로그래밍 언어의 차이를 조사하라.
**절차지향**    
순서대로 실행하는 방식이다. 위에서 아래로 코드가 흘러가고, 함수를 만들어서 반복되는 작업을 처리하는 방식이다. 대표적인 예로는 C언어가 있다.

**객체지향**

## 5. 라이브러리가 무엇인지 자세히 설명하시오.
라이브러리는 자주 사용되는 함수나 기능들을 미리 구현하여 재사용할 수 있도록 모아 놓은 코드들의 집합이다.

이로인해 프로그래머는 라이브러리를 사용하여 코딩을 하는데 있어 시간을 절약할 수 있고 코드 안정성을 높일 수 있다. 

---

## 6. 라이브러리가 목적파일 형태로 존재하는 이유를 설명하라.

첫째, 소스코드를 숨기기 위해서이다. 목적파일은 이미 컴파일된 상태라 내부 코드를 볼 수 없다. 기능은 제공하되 구현 방식은 보호할 수 있다.    
둘째, 컴파일 시간을 줄이기 위해서이다. 소스코드 형태라면 빌드할 때마다 라이브러리까지 다시 컴파일해야 한다. 목적파일은 이미 컴파일이 끝난 상태라 코드에 그냥 붙이면 된다.   
셋째, 다양한 언어에서 사용하기 위해서이다. 목적파일은 기계어에 가까운 형태라 언어에 종속되지 않는다. C로 만든 라이브러리를 C++이나 다른 언어에서도 쓸 수 있다.

## 7. 링크과정이 필요한 이유를 설명하라.
프로그램은 하나의 소스파일이 아니라 여러 개의 소스파일로 나누어 작성되는 경우가 많다.   
이러한 소스파일들은 컴파일을 하면 파일마다 목적파일이 따로 만들어지는데, 이 조각들은 아직 서로 연결되지 않은 상태이다. 링크는 이 조각들을 하나로 합쳐서 실제로 실행 가능한 프로그램을 만들어주는 과정이다.
링크가 없으면 ```printf()``` 같은 라이브러리 함수가 어디 있는지 찾지 못하고 각 코드의 메모리 주소도 확정할 수 없다.
