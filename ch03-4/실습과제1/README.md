# 실습과제

## 1. 접근지정자가 왜 필요한가?
접근 지정자는 외부에서로부터 객체의 내부 데이터를 보호하고, 프로그램을 더 안전하고 체계적으로 만들기 위해서이다. 데이터 보호(캡슐화), 잘못된 사용 방지, 코드의 구조화, 그리고 유지보수의 편의성을 위해 반드시 필요한 요소이다.

---

## 2. 생성자와 setter 멤버함수는 모두 멤버변수를 설정하는 기능이다. 차이점을 설명하라.

| 구분 | 생성자 | Setter |
|------|--------|--------|
| **호출 시점** | 객체 생성 시 단 한 번 | 객체 생성 후 언제든지 |
| **목적** | 객체의 초기화 | 멤버변수 값 변경 |
| **반환값** | 없음 (void도 아님) | 보통 void |
| **함수명** | 클래스명과 동일 | 자유롭게 지정 (set~) |
| **강제성** | 객체 생성 시 반드시 실행 | 필요할 때 선택적 호출 |

`생성자`는 객체가 생성될 때 단 한 번 자동 호출되어 초기값을 설정하고, `Setter`는 생성 이후 필요할 때마다 값을 변경하는 데 사용된다. 둘 다 멤버변수를 설정하지만 언제, 왜 설정하느냐가 가장 큰 차이점이다.

## 3.  객체지향형 언어의 특징인 캡슐화와정보은닉을 설명하라.
`캡슐화`는 객체의 데이터(멤버변수)와 기능(멤버함수)을 하나로 묶는 것이다. 관련된 데이터와 이를 처리하는 함수를 클래스 안에 함께 정의함으로써 객체가 독립적으로 동작할 수 있게 한다. `정보은닉`은 객체 내부의 데이터를 외부에서 직접 접근하지 못하도록 숨기는 것이다. `private` 접근 지정자로 멤버변수를 감추고, `public`으로 선언된 멤버함수(getter/setter)를 통해서만 접근하도록 제한한다.


**<캡슐화와 정보은닉은 같이 사용할 때의 장점>**
- 외부의 잘못된 접근으로부터 데이터를 보호한다.
- 내부 구현이 바뀌어도 외부 코드에 영향을 주지 않는다.
- 객체 간 독립성이 높아져 유지보수가 쉬워진다.
- 객체의 무결성을 유지한다.
