# 실습과제


## 1. 함수를 사용하는 이유를 설명하라.

함수를 사용하는 이유는 크게 세 가지이다. 첫째, **코드 재사용**으로 같은 코드를
반복해서 작성하지 않고 함수를 한 번 정의해두면 필요할 때마다 호출하여 사용할
수 있다. 둘째, **가독성**으로 복잡한 로직을 함수로 나누면 코드 구조가 명확해져 코드가 읽기 쉬워진다.
셋째, **유지보수**로 기능을 수정해야 할 때 해당 함수 하나만 고치면 그 함수를 사용하는
모든 곳에 자동으로 반영되어 수정이 쉽고 오류 발생 가능성도 줄어든다.

---

## 2. 짧은 코드를 갖는 함수를 자주 호출하면 발생하는 함수의 오버헤드를 설명하라.

함수를 호출할 때는 단순히 코드만 실행되는 것이 아니라, 매번 매개변수 전달, 반환 주소 저장, 지역 변수 생성, 스택 프레임 설정 및 복원 등의 추가 작업이 함께 이루어진다. 때문에 이러한 과정은 함수의 내용이 짧을수록 상대적으로 더 큰 비중을 차지하게 되어 결과적으로 프로그램의 실행 속도를 저하시킬 수 있다.

## 3. 12페이지 예제에서 인라인함수가 치환되면 private 멤버변수를 직접 접근하게 된다. 문법오류가 아닌가?

| 주체 | 코드 | 결과 |
|---|---|---|
| 사용자가 직접 작성 | `3.14 * radius * radius` | 오류 |
| 컴파일러가 인라인 치환 | `3.14 * radius * radius` | 정상 |

치환은 컴파일러가 **내부적**으로 하는 작업이고 `getArea()`가 Circle의 멤버함수임이 이미 검증된 상태이기 때문에 private 접근이 허용된다. 따라서 문법 오류가 아니다.

## 4. 인라인함수는 소스코드에서는 함수이지만 기계어로 번역되면 함수가 아니다. 이렇게 복잡하게 만든 이유를 설명하라. 다시 말해, 처음부터 함수를 안 쓰면 안되나요?

처음부터 함수를 사용하지 않고 코드를 직접 모두 작성할 수도 있지만 그렇게 하면 **코드의 구조**와 **유지보수성**이 크게 떨어진다. 함수는 프로그램을 모듈화하여 코드의 재사용성을 높이고 가독성을 좋게 만들며 수정이 필요할 때 한 곳만 고치면 되도록 해준다. 하지만 일반 함수는 호출할 때마다 함수 호출 오버헤드가 발생한다는 단점이 있다.
**인라인 함수**는 이 둘을 절충한 것으로 사람이 코드를 작성할 때는 함수로 편하게 쓰고 컴파일러가 기계어로 변환할 때는 호출을 없애버리는 방식이다. 즉, 사람을 위한 편의성과 기계를 위한 성능을 동시에 챙기는 해결책이다.
