# 실습과제


## 1. 함수를 사용하는 이유를 설명하라.

함수를 사용하는 이유는 크게 세 가지이다. 첫째, **코드 재사용**으로 같은 코드를
반복해서 작성하지 않고 함수를 한 번 정의해두면 필요할 때마다 호출하여 사용할
수 있다. 둘째, **가독성**으로 복잡한 로직을 함수로 나누면 코드 구조가 명확해져 코드가 읽기 쉬워진다.
셋째, **유지보수**로 기능을 수정해야 할 때 해당 함수 하나만 고치면 그 함수를 사용하는
모든 곳에 자동으로 반영되어 수정이 쉽고 오류 발생 가능성도 줄어든다.

## 2. 짧은 코드를 갖는 함수를 자주 호출하면 발생하는 함수의 오버헤드를 설명하라.

함수를 호출할 때마다 다음 과정이 발생해요.

1. 현재 위치 저장
2. 매개변수 스택 복사
3. 함수로 점프
4. 함수 실행
5. 반환값 저장
6. 원래 위치 복귀

코드가 한 줄짜리인 짧은 함수를 수천 번 호출하면, 실제 계산보다 이 **준비/복귀 과정**이 더 오래 걸릴 수 있어요. 이게 함수 호출 오버헤드예요.

## 3. 12페이지 예제에서 인라인함수가 치환되면 private 멤버변수를 직접 접근하게 된다. 문법오류가 아닌가?

문법오류가 아니에요. 12페이지 예제처럼 `cir.getArea()`가 `3.14 * radius * radius`로 치환될 때, `radius`는 private이지만 오류가 나지 않아요.

| 주체 | 코드 | 결과 |
|---|---|---|
| 프로그래머가 직접 작성 | `3.14 * radius * radius` | 오류 |
| 컴파일러가 인라인 치환 | `3.14 * radius * radius` | 정상 |

치환은 컴파일러가 **내부적**으로 하는 작업이고, `getArea()`가 Circle의 멤버함수임이 이미 검증된 상태이기 때문에 private 접근이 허용돼요.

## 4. 인라인함수는 소스코드에서는 함수이지만 기계어로 번역되면 함수가 아니다. 이렇게 복잡하게 만든 이유를 설명하라. 다시 말해, 처음부터 함수를 안 쓰면 안되나요?
처음부터 코드를 직접 복붙하면 성능은 같지만, 함수의 장점을 모두 잃어요.

| | 코드 직접 복붙 | 인라인 함수 |
|---|---|---|
| 성능 | 빠름 | 빠름 |
| 코드 중복 | 중복 많음 | 한 곳에 정의 |
| 가독성 | 나쁨 | 좋음 |
| 유지보수 | 어려움 | 쉬움 |

인라인 함수는 **"함수의 장점(재사용, 가독성, 유지보수) + 성능(오버헤드 없음)"** 을 동시에 얻기 위한 방법이에요.
직접 복붙하면 성능은 같아도 Q1의 함수 장점을 전부 포기해야 하니까요.
